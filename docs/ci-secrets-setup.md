# CI Secrets & Environment Variables Guide

This document explains the repository secrets and environment variables utilized by the multi-platform GitHub Actions build workflow (`.github/workflows/build.yml`).

---

## 1. Building Key (CurseForge API)

| Secret Name | Required? | Purpose |
| :--- | :--- | :--- |
| `CURSEFORGE_API_KEY` | Optional (Recommended) | Embedded at compile-time into `zircon-server` (`crates/zircon-server/build.rs`). Used for fetching Minecraft mod metadata, modpack definitions, and file distributions. If omitted in secrets, the build falls back to the embedded public default key. |

To configure in GitHub:
1. Go to your GitHub Repository -> **Settings** -> **Secrets and variables** -> **Actions**.
2. Click **New repository secret**.
3. Name: `CURSEFORGE_API_KEY`
4. Value: `<Your CurseForge API Key>`

---

## 2. Tauri Updater Signing Keys

| Secret Name | Required? | Purpose |
| :--- | :--- | :--- |
| `TAURI_SIGNING_PRIVATE_KEY` | Recommended | Minisign private key string generated by Tauri (`tauri signer generate`). Used to digitally sign updater payload binaries. |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | Recommended | Plaintext password decrypting `TAURI_SIGNING_PRIVATE_KEY`. |

> [!NOTE]
> If `TAURI_SIGNING_PRIVATE_KEY` is not detected in GitHub Secrets (e.g., in a PR from a fork), the build automatically disables `createUpdaterArtifacts` dynamically so the build succeeds without error. When present, signed updater `.sig` and updater metadata will be generated.

## 3. Microsoft Azure Code Signing (Windows)

The Windows job automatically checks for Azure credentials. If absent, it logs `No Microsoft Azure signing credentials detected. Skipping Windows code signing.` and produces unsigned installers (`.exe` and `.msi`).

When you are ready to enable Azure code signing (via Azure Key Vault or Azure Trusted Signing), add:

| Secret Name | Purpose |
| :--- | :--- |
| `AZURE_TENANT_ID` | Azure Active Directory Tenant ID |
| `AZURE_CLIENT_ID` | Service Principal / App Registration Client ID |
| `AZURE_CLIENT_SECRET` | Service Principal Client Secret |
| `AZURE_KEY_VAULT_URI` | Azure Key Vault URI (e.g., `https://myvault.vault.azure.net/`) |
| `AZURE_CERT_NAME` | Name of the code-signing certificate inside the Key Vault |

---

## 4. Apple Developer Code Signing & Notarization (macOS)

The macOS job automatically checks for Apple Developer credentials. If absent, it logs `No Apple Developer certificate detected. Skipping macOS code signing and notarization.` and builds ad-hoc / unsigned `.dmg` and `.app` bundles.

When you are ready to enable Apple code signing and notarization:

| Secret Name | Purpose |
| :--- | :--- |
| `APPLE_CERTIFICATE` | Base64-encoded `.p12` file containing your Apple Developer ID Application certificate and private key. |
| `APPLE_CERTIFICATE_PASSWORD` | Password for the `.p12` certificate. |
| `APPLE_SIGNING_IDENTITY` | The common name of the certificate (e.g. `Developer ID Application: Your Name (TEAM_ID)`). |
| `APPLE_ID` | Apple ID email used for notarization. |
| `APPLE_PASSWORD` | App-specific password generated on appleid.apple.com for notarization. |
| `APPLE_TEAM_ID` | 10-character Apple Developer Team ID. |

## 5. Artifacts Produced by Platform

| Platform | Runner | Server Artifacts | Launcher Artifacts |
| :--- | :--- | :--- | :--- |
| **Windows** | `windows-latest` | `zircon-server-windows-x86_64.zip` | NSIS `.exe`, WiX `.msi` (+ `.sig`) |
| **Linux** | `ubuntu-22.04` | `zircon-server-linux-x86_64.tar.gz` | Debian `.deb`, AppImage `.AppImage`, Red Hat / Fedora `.rpm` (+ `.sig`) |
| **macOS** | `macos-latest` | *(Not compiled)* | Apple Disk Image `.dmg`, macOS App Bundle `Zircon.app` (+ `.sig`) |
